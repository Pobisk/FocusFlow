Концепция алгоритма выбора задачи (черновик)

Нам нужно рассчитать какую задачу следует взять в работу сейчас.

ВАЖНО: чтобы корректно определить на бэке дату сегодня, мы с фронта передаем дату сегодня, время = 00:00 в локальном времени клиента

Фильтрация:
Мы берем все активные задачи на сегодня. 
То есть: задача активна и "сегодня" >= "дата старта" и "сегодня" <= "дата финиша"

чтобы определить пересечение с текущим моментом, для задачи-встречи вычисляем:
реальная дата-время начала = "дата-время встречи" - "время на дорогу в минутах"
реальная дата-время финиша = "дата-время встречи" + "длительность (затраты времени планируемые в минутах)"

Если на текущий момент времени есть задача-встреча, то возвращаем её.
Иначе, смотрим сколько минут N у нас есть до ближайшей задачи-встречи. Если встреч на сегодня больше нет, то N = int.Max()
Далее убираем из списка задачи-встречи.
Далее убираем из списка отложенные задачи, те у которых delay-to > текущего момента времени.
Далее убираем из списка задачи, плановое время выполнения которых > N, то есть мы не успеем их сделать до начала следующей встречи.

Для оставшихся задач в списке, мы вычисляем некую количественную оценку Score, затем сортируем по убыванию и берем TOP 1

На оценку влияют: 
1) параметры задачи 
- целевая задача (есть привязка к цели)
- "Важность" 
- "Последствия"
- "Времени до дедлайна" здесь например так: берем период задачи, разделяем его на 3 части, находим текущий момент времени на этом периоде. далее для 1-й части функция y=x, для 2-й части функция y=0.3*x, для 3-й части функция y=2*x
- количество отказов выполнять действие

2) параметры проекта
- низкая скорость проекта (см. экран Список проектов п.3)

3) параметры сферы
- низкая оценка удовлетворенности в данной сфере

Все параметры влияют со своими коэффициентами, которые пользователь может менять в настройках (см. сущности п.7)
