# ТЗ-08: Итоги дня

## 1. Цель модуля

Предоставить пользователю сводку за сегодня: какие действия выполнены, какие просрочены, какие активны, сколько времени потрачено. Это ключевой экран для получения чувства удовлетворённости в конце дня и для планирования следующего дня.

## 2. Зависимости

- Модуль **01 — Авторизация** (защита эндпоинтов).
- Модуль **05 — Действия** (статусы действий, TimeLog).
- Модуль **07 — Алгоритм выбора действия** (сортировка по Score).

## 3. Концепция

Экран "Итоги дня" показывает:
1. **Summary-строка**: сколько времени работали сегодня, в том числе над целевыми (проактивными) действиями.
2. **Завершённые действия** (зелёные) — вверху списка.
3. **Отменённые действия** (синие).
4. **Просроченные действия** (красные) — нужно было завершить сегодня или раньше.
5. **Действия на ближайшие N дней** (жёлтые) — настраивается (по умолчанию 3 дня).
6. **Остальные активные действия**.

Все действия отсортированы по Score (алгоритм выбора).

## 4. Backend

### 4.1. Эндпоинт

Файл: `backend/src/api/endpoints/day_summary.py`

Защищён `Depends(get_current_user)`.

#### GET /api/day-summary

Параметры запроса:
- `date: str | None` — дата в формате "YYYY-MM-DD" (по умолчанию сегодня, UTC)
- `yellow_threshold_days: int = 3` — сколько дней вперёд считать "жёлтыми"

Выход:

```python
class DaySummaryResponse(BaseModel):
    date: str  # "YYYY-MM-DD"
    total_worked_minutes: int  # общее время работы сегодня
    proactive_worked_minutes: int  # время над целевыми действиями
    completed_actions: list[ActionRead]  # завершённые сегодня
    cancelled_actions: list[ActionRead]  # отменённые сегодня
    overdue_actions: list[ActionRead]  # просроченные (end_date <= today)
    upcoming_actions: list[ActionRead]  # ближайшие (end_date <= today + N дней)
    other_actions: list[ActionRead]  # остальные активные
```

Логика:
1. Определить начало и конец дня в UTC для указанной даты.
2. Найти все TimeLog за сегодня для `user_id` → суммировать `duration_minutes`.
3. Из них — только те, что относятся к действиям с `goal_id is not null` (через проект).
4. Найти все активные действия пользователя.
5. Разделить на группы:
   - `completed`: статус "completed" и updated_at попадает в сегодня
   - `cancelled`: статус "cancelled" и updated_at попадает в сегодня
   - `overdue`: статус "active", end_date <= сегодня
   - `upcoming`: статус "active", end_date > сегодня и <= сегодня + N дней
   - `other`: все остальные активные
6. Каждую группу отсортировать по Score DESC.
7. Вернуть результат.

## 5. Frontend

### 5.1. Страница итогов дня

Путь: `/day-summary` (доступна только авторизованным)

**Отображение:**

**Summary-строка (вверху, крупно):**
- "Сегодня отработано: 3ч 45м"
- "Из них над целями: 1ч 20м"
- Процент целевого времени

**Секция "Завершено" (зелёный фон/бордер):**
- Список действий, завершённых сегодня
- Каждое действие: код сферы, название, фактическое время

**Секция "Отменено" (синий фон/бордер):**
- Список отменённых сегодня действий

**Секция "Просрочено" (красный фон/бордер):**
- Действия, которые нужно было завершить сегодня или раньше
- Выделяются красным цветом

**Секция "На очереди" (жёлтый фон/бордер):**
- Действия, которые нужно завершить в ближайшие N дней

**Секция "Остальные":**
- Все остальные активные действия

**Действия на странице:**
- При клике на действие — открыть карточку действия для редактирования
- Кнопка "Взять в работу" — запускает фокус-сессию с этим действием
- Кнопка "Внести время" — модальное окно для ручного ввода времени (если не использовался таймер)
- Кнопка "Обновить" — перезагрузить данные

### 5.2. Ручной ввод времени

Модальное окно:
- Действие (выпадающий список активных действий)
- Время в минутах
- Примечание (опционально)
- Кнопка "Сохранить" → создаёт TimeLog с `duration_minutes` без `started_at`/`ended_at`

- [ ] Эндпоинт `/api/day-summary` возвращает корректные данные.
