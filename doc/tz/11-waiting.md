# ТЗ-11: Ожидающие

## 1. Цель модуля

Реализовать список действий, которые находятся в статусе "ожидания" — пользователь выполнил свою часть работы и теперь ждёт результата от кого-то другого (ответ на письмо, документ, решение и т.п.). Система напоминает, когда нужно проверить статус.

## 2. Зависимости

- Модуль **01 — Авторизация** (защита эндпоинтов).
- Модуль **05 — Действия** (действия со статусом "waiting").

## 3. Концепция

Когда пользователь выполнил все необходимые действия по задаче, но результат зависит от внешнего исполнителя, он переводит действие в статус "waiting", указывает исполнителя и дату, когда нужно проверить результат.

Действия в статусе "waiting" не участвуют в алгоритме выбора и не отображаются в списке активных действий. Они отображаются только в разделе "Ожидающие".

## 4. Backend

### 4.1. Эндпоинты

Файл: `backend/src/api/endpoints/waiting.py`

Защищены `Depends(get_current_user)`.

#### GET /api/waiting

Параметры запроса:
- `overdue_only: bool = False` — только просроченные (check_at <= now)
- `sphere_id: UUID | None` — фильтр по сфере (через проект)

Выход: список `ActionRead` (только со статусом "waiting")

Логика:
- Выбрать все действия пользователя со статусом "waiting".
- Присоединить информацию о проекте и сфере.
- Отсортировать по `check_at ASC` (сначала те, которые нужно проверить раньше).
- Если `overdue_only = True`, отфильтровать только те, у которых `check_at <= now`.

#### PUT /api/waiting/{action_id}/check

Выход: `ActionRead`

Логика:
- Найти действие по `action_id`.
- Если результат получен — установить статус "completed".
- Если нужно подождать ещё — обновить `check_at` на новую дату.
- Вернуть обновлённое действие.

#### PUT /api/waiting/{action_id}/postpone

Вход: `{ "new_check_at": datetime }`
Выход: `ActionRead`

Логика:
- Перенести дату проверки на новую.
- Вернуть обновлённое действие.

## 5. Frontend

### 5.1. Страница ожидающих

Путь: `/waiting` (доступна только авторизованным)

**Отображение:**
- Фильтр по сферам (компонент `SphereFilter`).
- Переключатель "Все" / "Просроченные".
- Список действий в статусе "waiting":
  - Код сферы
  - Название действия
  - Название проекта
  - Исполнитель
  - Дата проверки (сколько дней осталось / просрочено)
  - Статус (в норме / просрочено)

**Цветовая маркировка:**
- Зелёный: check_at > now + 3 дня
- Жёлтый: now < check_at <= now + 3 дня
- Красный: check_at <= now (просрочено)

**Действия:**
- Кнопка "Проверить" — модальное окно:
  - "Результат получен" → статус "completed"
  - "Ожидаю дальше" → новая дата проверки
- Кнопка "Перенести" — выбор новой даты проверки
- При клике на действие — открыть карточку действия

### 5.2. Интеграция с итогами дня

На странице итогов дня, если есть просроченные ожидающие, показывать уведомление:
"N действий ожидают проверки (из них M просрочено)"
