# ТЗ-12: История проектов

## 1. Цель модуля

Предоставить доступ к архиву завершённых и отменённых проектов/задач с возможностью поиска по тексту и фильтрации по сфере и периоду. Пользователь может найти информацию из прошлых проектов (контакты, документы, комментарии, описания).

## 2. Зависимости

- Модуль **01 — Авторизация** (защита эндпоинтов).
- Модуль **04 — Проекты и задачи** (проекты со статусом "completed" или "cancelled").
- Модуль **05 — Действия** (действия завершённых проектов).

## 3. Концепция

История — это read-only просмотр завершённых/отменённых проектов. Пользователь не может редактировать проекты в истории, но может просматривать их детали: описание, чек-лист, действия, комментарии (комментарии будут добавлены позже).

## 4. Backend

### 4.1. Эндпоинты

Файл: `backend/src/api/endpoints/history.py`

Защищены `Depends(get_current_user)`.

#### GET /api/history/projects

Параметры запроса:
- `sphere_id: UUID | None` — фильтр по сфере
- `status: str | None` — фильтр по статусу ("completed" | "cancelled")
- `date_from: datetime | None` — начало периода (по updated_at)
- `date_to: datetime | None` — конец периода
- `search: str | None` — текстовый поиск (по title, description)
- `page: int = 1` — пагинация
- `page_size: int = 20` — размер страницы

Выход:

```python
class HistoryProjectRead(BaseModel):
    id: UUID
    sphere_id: UUID
    sphere_code: str
    sphere_name: str
    goal_id: Optional[UUID]
    goal_title: Optional[str]
    title: str
    description: Optional[str]
    project_type: str
    status: str
    start_date: Optional[datetime]
    target_date: Optional[datetime]
    completed_at: Optional[datetime]  # когда завершён (updated_at в момент смены статуса)
    actions_count: int  # количество действий
    created_at: datetime
    updated_at: datetime

class HistoryResponse(BaseModel):
    items: list[HistoryProjectRead]
    total: int
    page: int
    page_size: int
    total_pages: int
```

Логика:
1. Выбрать проекты для `user_id` со статусом "completed" или "cancelled".
2. Применить фильтры.
3. Если `search` передан — искать в `title` и `description` (ILIKE).
4. Отсортировать по `updated_at DESC`.
5. Вернуть с пагинацией.

#### GET /api/history/projects/{project_id}

Выход: `ProjectRead` (полная информация о проекте, включая действия)

Логика:
- Найти проект по `project_id` и `user_id`.
- Вернуть проект со всеми действиями (включая завершённые).

#### GET /api/history/search

Параметры запроса:
- `q: str` — поисковый запрос (обязательный)
- `sphere_id: UUID | None` — фильтр по сфере

Выход: список `HistoryProjectRead`

Логика:
- Поиск по `title` и `description` проектов + по `title` действий.
- Вернуть проекты, где найдено совпадение.

## 5. Frontend

### 5.1. Страница истории

Путь: `/history` (доступна только авторизованным)

**Отображение:**
- Фильтр по сферам (компонент `SphereFilter`).
- Фильтр по статусу: "Завершённые" / "Отменённые" / "Все".
- Фильтр по периоду: кнопки "Назад" / "Вперед" (по кварталам), отображается текущий квартал.
- Поле поиска (текстовый ввод).
- Список проектов в виде карточек:
  - Код сферы
  - Название
  - Тип (проект/задача)
  - Статус (завершён / отменён)
  - Дата завершения
  - Количество действий
  - Кнопка "Открыть"

**Действия:**
- При клике на проект — открыть детальную информацию:
  - Описание
  - Чек-лист (с отметками о выполнении)
  - Список действий (все, включая завершённые)
  - По каждому действию: название, статус, фактическое время
- Пагинация (если проектов больше 20).

### 5.2. Поиск

Поле поиска работает в реальном времени (с debounce 300-500ms) или по нажатию Enter. Результаты поиска отображаются в том же списке, заменяя стандартную выдачу.
