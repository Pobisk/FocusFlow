# ТЗ-06: Рабочий процесс (фокус-сессии)

## 1. Цель модуля

Реализовать основной рабочий процесс: пользователь нажимает "Работа", система предлагает одно действие (через алгоритм выбора), запускается таймер фокус-сессии. Пользователь работает, не отвлекаясь, пока не завершит действие или не остановит таймер.

## 2. Зависимости

- Модуль **01 — Авторизация** (защита эндпоинтов).
- Модуль **05 — Действия** (работаем с действиями и TimeLog).
- Модуль **07 — Алгоритм выбора действия** (получаем TOP-1 действие).

## 3. Концепция

Главный принцип: **одна задача на экране**. Когда пользователь в фокус-сессии, он видит только текущее действие. Никаких списков, никаких других задач. Только "Сейчас: [действие]".

Поток работы:
1. Пользователь на главном экране нажимает "Работа".
2. Система запускает алгоритм выбора → получает TOP-1 действие.
3. Отображается карточка действия с кнопками "Начать" / "Отложить".
4. Пользователь нажимает "Начать" → запускается таймер.
5. Во время сессии: таймер тикает, кнопки "Пауза" / "Стоп".
6. По окончании: система показывает итог сессии, предлагает перевести действие в "Завершено" или оставить активным.

## 4. Backend

### 4.1. Эндпоинты

Файл: `backend/src/api/endpoints/workflow.py`

Все эндпоинты защищены `Depends(get_current_user)`.

#### GET /api/workflow/next-action

Выход: `ActionRead | null` (рекомендованное действие или null, если нет доступных)

Логика:
- Вызвать алгоритм выбора действия (ТЗ-07).
- Вернуть TOP-1 действие.
- Если действий нет — вернуть `null`.

#### POST /api/workflow/start-session

Вход: `{ "action_id": UUID }`
Выход: `{ "session_id": UUID, "started_at": datetime }`

Логика:
- Проверить, что действие принадлежит `user_id` и имеет статус "active".
- Создать запись в `TimeLog` с `started_at = now()`.
- Вернуть ID сессии и время старта.

#### POST /api/workflow/pause-session

Вход: `{ "session_id": UUID }`
Выход: `{ "paused_at": datetime, "total_duration_minutes": int }`

Логика:
- Найти TimeLog по `session_id`.
- Записать промежуточное время (можно хранить паузы в отдельной таблице или просто запоминать).
- Вернуть общее время сессии на момент паузы.

#### POST /api/workflow/resume-session

Вход: `{ "session_id": UUID }`
Выход: `{ "resumed_at": datetime }`

Логика:
- Продолжить отсчёт времени для той же сессии.

#### POST /api/workflow/stop-session

Вход: `{ "session_id": UUID, "action_status": str | None }`
Выход: `{ "ended_at": datetime, "duration_minutes": int }`

Логика:
- Найти TimeLog по `session_id`.
- Установить `ended_at = now()`.
- Вычислить `duration_minutes`.
- Обновить `actual_duration_minutes` в действии (сумма всех TimeLog для этого действия).
- Если передан `action_status` ("completed" или "waiting") — обновить статус действия.
- Вернуть итоги сессии.

#### POST /api/workflow/refuse-action

Вход: `{ "action_id": UUID, "reason": str }`
Выход: `ActionRead`

Логика:
- Увеличить `refusal_count` действия на 1.
- Сохранить причину отказа.
- Если `refusal_count >= 3` — отметить действие для пересмотра приоритетов.
- Вернуть обновлённое действие.

### 4.2. Таблица отказов (опционально)

Для анализа причин отказов можно создать таблицу:

```python
class RefusalLog(BaseModel, table=True):
    __tablename__ = "refusal_logs"

    user_id: UUID = Field(foreign_key="users.id", nullable=False, index=True)
    action_id: UUID = Field(foreign_key="actions.id", nullable=False, index=True)
    reason: str = Field(nullable=False, max_length=500)
    refused_at: datetime = Field(nullable=False)
```

## 5. Frontend

### 5.1. Главный экран

Путь: `/` (доступен только авторизованным)

**Отображение (минималистичное):**
- Крупная кнопка "Работа" (основное действие).
- Кнопка "Задача" (быстрое добавление проекта/задачи).
- Кнопка "Итог дня".
- Внизу: ссылки на разделы (Цели, Проекты, История, КНМБ, Ожидающие, Календарь, Отчёт).

### 5.2. Экран фокус-сессии

Путь: `/focus` (открывается после нажатия "Работа")

**Состояние 1: Предложение действия**
- Крупная карточка с действием:
  - Код сферы + название проекта
  - Название действия
  - Важность / последствия (иконками)
  - Плановое время
  - Дедлайн (если есть)
- Кнопки: "Начать" / "Отложить" (с причиной)

**Состояние 2: Фокус-сессия (таймер запущен)**
- Крупный таймер (ЧЧ:ММ:СС)
- Название действия (мелко, чтобы не отвлекало)
- Кнопки: "Пауза" / "Стоп"
- При паузе: таймер замирает, кнопка "Продолжить"

**Состояние 3: Итог сессии**
- "Сессия завершена"
- Фактическое время
- Кнопки:
  - "Завершить действие" → статус "completed"
  - "Оставить активным" → статус остаётся "active"
  - "В ожидание" → статус "waiting" (с указанием исполнителя и срока проверки)
- После выбора — возврат на главный экран

### 5.3. Быстрое добавление задачи

Модальное окно с минимальным набором полей:
- Название (обязательно)
- Сфера (выпадающий список)
- Цель (опционально)
- Плановое время (опционально)

Создаётся проект типа "task" с одним пустым действием.
