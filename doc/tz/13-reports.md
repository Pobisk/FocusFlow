# ТЗ-13: Отчёты

## 1. Цель модуля

Предоставить пользователю визуальную аналитику затраченного времени. Отчёты показывают, сколько времени потрачено на работу (общее) и сколько из этого — на целевые (проактивные) действия. Данные отображаются в виде гистограмм с возможностью переключения периодов.

## 2. Зависимости

- Модуль **01 — Авторизация** (защита эндпоинтов).
- Модуль **05 — Действия** (TimeLog, признак проактивности через проект).

## 3. Концепция

Отчёты показывают гистограммы в четырёх разрезах:
- **Неделя** — 7 столбиков (Пн-Вс)
- **Месяц** — столбики по дням
- **Квартал** — столбики по неделям
- **Год** — столбики по месяцам

Каждый столбик показывает:
- Общая высота = общее время работы
- Закрашенная часть = время над целевыми (проактивными) действиями

## 4. Backend

### 4.1. Эндпоинт

Файл: `backend/src/api/endpoints/reports.py`

Защищён `Depends(get_current_user)`.

#### GET /api/reports/time

Параметры запроса:
- `period: str` — "week" | "month" | "quarter" | "year"
- `offset: int = 0` — смещение относительно текущего периода (0 = текущий, -1 = предыдущий, 1 = следующий)

Выход:

```python
class ReportBar(BaseModel):
    label: str  # подпись: "Пн", "Вт" или "01.04", "Апрель" и т.п.
    total_minutes: int  # общее время
    proactive_minutes: int  # время над целевыми действиями

class ReportResponse(BaseModel):
    period: str
    offset: int
    bars: list[ReportBar]
    total_minutes: int  # итого за период
    proactive_minutes: int  # итого целевых за период
    proactive_percent: float  # процент целевого времени
```

Логика:

**Для period = "week":**
1. Определить начало и конец текущей недели (Пн 00:00 UTC — Вс 23:59 UTC) с учётом `offset`.
2. Для каждого дня недели:
   - Найти все TimeLog за этот день для `user_id`.
   - Суммировать `duration_minutes`.
   - Из них — только те, что относятся к действиям с `goal_id is not null` (проактивные).
3. Вернуть 7 столбиков.

**Для period = "month":**
1. Определить начало и конец месяца с учётом `offset`.
2. Для каждого дня месяца — аналогично.

**Для period = "quarter":**
1. Определить начало и конец квартала с учётом `offset`.
2. Для каждой недели квартала — сгруппировать TimeLog по неделям.

**Для period = "year":**
1. Определить начало и конец года с учётом `offset`.
2. Для каждого месяца — сгруппировать TimeLog по месяцам.

### 4.2. Дополнительный эндпоинт: сводка по сферам

#### GET /api/reports/by-sphere

Параметры запроса:
- `date_from: str` — начало периода (ISO, UTC)
- `date_to: str` — конец периода (ISO, UTC)

Выход:

```python
class SphereReportItem(BaseModel):
    sphere_id: UUID
    sphere_code: str
    sphere_name: str
    total_minutes: int
    proactive_minutes: int

class SphereReportResponse(BaseModel):
    items: list[SphereReportItem]
    total_minutes: int
```

Логика:
- Сгруппировать TimeLog по сферам (через action → project → sphere).
- Для каждой сферы: общее время и целевое время.

## 5. Frontend

### 5.1. Страница отчётов

Путь: `/reports` (доступна только авторизованным)

**Отображение:**

**Переключатель периода:**
- Кнопки: "Неделя" "Месяц" "Квартал" "Год"
- Активная кнопка выделена

**Навигация:**
- Кнопки "Назад" / "Вперед" для переключения между периодами
- Подпись текущего периода: "24-30 марта 2026" или "Март 2026" и т.п.

**Гистограмма:**
- Столбики одинаковой ширины, расположены равномерно
- Высота столбика пропорциональна общему времени
- Закрашенная часть (другим цветом) — целевое время
- Под каждым столбиком — подпись (день недели, дата или месяц)
- При наведении на столбик — всплывающая подсказка с точными значениями

**Summary под гистограммой:**
- "Всего: Xч Yм"
- "Целевых: Xч Yм (Z%)"

**Дополнительно: отчёт по сферам**
- Таблица или круговая диаграмма, показывающая распределение времени по сферам за выбранный период.
